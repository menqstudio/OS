# CI dependency lockfile — installed with `pip install --require-hashes`.
#
# Every package in the full transitive closure of the two direct dependencies
# (jsonschema, cryptography) is pinned to an exact version and to the sha256 digests
# PUBLISHED BY PyPI (the `digests.sha256` field, not locally computed). --require-hashes
# then refuses any wheel whose hash is not listed, so a compromised or substituted
# package cannot enter the build. Binary packages carry both the manylinux x86_64 and
# SUPPORTED INTERPRETERS: CPython 3.12 (what CI pins) and CPython 3.13, on linux x86_64 and the
# platforms the pure-python and abi3 wheels already cover. A 3.13 box originally hit
# "THESE PACKAGES DO NOT MATCH THE HASHES" on rpds-py and would have hit it on cffi: both ship a
# wheel per Python version, only the 3.12 ones were listed, and pip cannot tell "a wheel we never
# listed" from "a wheel somebody swapped". Refusing was correct — the fix is to list what we intend
# to support, not to relax the check.
#
# Every added hash is PyPI's published `digests.sha256`, never a digest computed from a downloaded
# file: a locally computed hash of a tampered download matches the tampered download.
#
# Kept deliberately narrow — not musl, not aarch64, not every wheel PyPI holds. Each extra hash is
# another artifact this gate will accept.

# the win_amd64 cp312 wheels so the one file installs on the ubuntu and windows runners.
#
# To refresh after a version bump: re-fetch each package's PyPI JSON and copy the
# published sha256 for the cp312 wheels (pure packages: the py3-none-any wheel).
