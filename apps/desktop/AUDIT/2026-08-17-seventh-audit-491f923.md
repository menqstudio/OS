## PR #149 — commit message, verbatim

```
Repo-state survives a GraphQL outage without weakening (#149)

* Repo-state survives a GraphQL outage without weakening (found live, today)

WHAT HAPPENED
GitHub reported a Partial System Outage. GraphQL (v4) returned HTTP 503 to every
call; REST (v3) answered correctly throughout. `gh pr view` and `gh pr list`
speak v4 exclusively, so every pull-request read in check_repo_state.py went down
at once, the new fail-closed refusals fired, and main went red.

The refusals were RIGHT — "a check that could not run has not passed" is A-11's
and G-05's whole point, and before those changes this would have printed GREEN on
unread data. But two decisions taken the same day compounded:

  * the refusals (A-11, G-05), and
  * Repo-state becoming a REQUIRED status check on main (G-01).

Together they mean a GitHub v4 outage blocks every merge in the repository.

WHY THE FIX IS A SECOND ROAD AND NOT A RELAXATION
Neither half should be undone. The refusal is correct and the required context is
correct. What is wrong is that one transport was a single point of failure for a
fact two transports can serve: `gh api repos/…/pulls/148` returned the state, the
merge commit, the head sha, the base ref and the draft flag while v4 was down.

So `fetch_live`, `fetch_carrier` and `open_prs_now` fall back to REST. THE
FAIL-CLOSED PROPERTY IS UNCHANGED: if both roads fail the caller still gets None
and still refuses. This removes only the case where one API is down and the other
is answering.

Two details that are load-bearing rather than cosmetic:
  * REST reports a merged PR as `state: "closed"` with `merged: true`, GraphQL as
    `MERGED`. Mapping it to CLOSED would tell verify_settled_snapshot the wrong
    story, so the mapping is explicit.
  * the open-PR list is paginated. A truncated list would read as "these are all
    the open pull requests", and that function's whole contract is that the set is
    complete — so a partial read returns None rather than what it managed to get.

Verified against the live outage: with v4 still returning 503, the gate is GREEN
and read everything it needed from v3.
```
